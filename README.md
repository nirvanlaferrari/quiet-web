# Quiet Web

A browser-first RSS/Atom reader. Run `npm.cmd install` then `npm.cmd start`; production uses Vercel Node functions with Supabase. Set SUPABASE_URL and SUPABASE_SECRET_KEY only in the server environment. Run migrations in supabase/migrations in order. Build: `node scripts/build-vercel.cjs`.

## Browser/server boundary

## Extended feature checklist
- Transparent reasons: aggregate cards identify a supporting publisher/pairing or popularity; blogroll-boosted results name the submitted source. Editorial/demo picks never claim measured feedback.
- Ranking safeguards: signed single-use tokens, bounded input, minimum three accepted batches and weighted support >=2, large/repetitive batch downweighting, logarithmic popularity/co-subscription score and hostname diversity. Batches do not prove unique people.
- Background feed refresh: foreground-online 15-minute refresh, timeout/backoff, no read-state or full-text loss.
- Conditional requests: browser stores ETag/Last-Modified in `quiet-web-feed-sync`; proxy forwards If-None-Match/If-Modified-Since and returns 304 metadata. Unchanged content is not reparsed or reimported.
- robots.txt: proxy uses robots-parser for QuietWebReader, follows validated redirects, respects path rules, permits unavailable 4xx policy files, and refuses fetching while robots policy is unreachable/5xx. Policy retrieval is bounded. Robots rules are policy data, not server-side feed/article parsing. Rules are fetched per request rather than storing publisher pages. See RFC 9309 and RFC 9110.
- OPML: Library imports XML under 2 MB, rejects DOCTYPE/entity declarations, supports nested folder labels, deduplicates URLs, previews selectable feeds and imports sequentially (cap 100). Existing feeds are not duplicated. Individual failures are reported. Export includes public subscriptions and tags using XML serialization; no article/highlight backup is implied. Optional sharing is suppressed during bulk imports and attempted once afterward.
- Feed tags: Library → Subscriptions & organisation. Select feed, set comma-separated tags, Save; Timeline has an All tags filter. Tags stay local and round-trip through OPML category attributes.
- Blogrolls: browser scans explicit `.blogroll`, `.linkcat`, `#blogroll` and friend/colleague links on the publisher homepage after follow or Library re-scan. Local detections persist. A separate opt-in plus Submit sends at most 20 A→B edges with a single-use token to POST /api/discovery/blogroll. The server validates URLs and unions at most 100 outgoing edges per publisher. Repeated identical edges do not add score. Eligible ranked targets gain a bounded .15 boost from a matching followed source.
- Graph: article completion opens the accessible SVG/HTML graph, prioritizing detected blogroll neighbours, then aggregate/editorial suggestions. Reasons reveal provenance. Follow uses the real importer.

Blogroll threat-model addition: client-submitted links are claims, not proof that the submitter owns A or that A actually links to B. The server deliberately does not parse publisher HTML. Link influence is small, cannot bypass minimum real submission support, and repeated same-source edges do not multiply it. Determined attackers can still forge multiple public source domains; independent verification/moderation would be required for a large public launch. LocalStorage contains tag/link preferences, not user IDs. Source URLs are public blog identities, not persistent reader identities.

New check: `node scripts/test-final-features.cjs`; full DOM harness: `node scripts/test-app-boot.cjs`. These do not substitute for real voice playback, real-browser service-worker offline reload, or unknown judging sites. No new database migration is required for edges/tags/OPML/validators, since the aggregate state table already stores structured JSON. Previously supplied privacy/seed migrations still apply if not already run.

Standards: https://2005.opml.org/spec2.html, https://www.rfc-editor.org/rfc/rfc9309, https://www.rfc-editor.org/rfc/rfc9110.

## Demo seed data
`samples/seed-blogs.json` contains 12 real blogs verified through the same fetch proxy and browser parser; WordPress feeds are preferred. `scripts/verify-seed-blogs.cjs` records checks without storing publisher content. `demo-bootstrap.js` loads these as suggestions on a fresh browser; it never auto-subscribes visitors or submits their lists.

Run `supabase/migrations/003_demo_discovery_dataset.sql` once to populate the separate `discovery-demo-v1` dataset. It is synthetic subscription-group evidence for demo availability, not real users or actual engagement. Existing live submissions and view counts are unchanged. The API uses genuine supported results first and demo editorial results only for a cold start. Demo cards never claim measured reader counts. Re-running the SQL does not overwrite an existing seed row.

Verification scripts: test-feed-handling.cjs (generic RSS/Atom/autodiscovery/failure fixtures), verify-live-reader.cjs (read-only live API and three article checks), test-demo-dataset.cjs (seed counts, exclusion and release assets). Reports under outputs are point-in-time evidence. Hidden judges' sites and real-browser offline reload remain unverified until those tests are actually performed. Fresh publishers can still change formats, block requests, or exceed the import size limit later.
All feed parsing, Readability extraction, DOMPurify sanitization and article caching run in the browser. The fetch proxy transports unparsed text and does not persist content. Supabase stores discovery aggregates, replay protection and counters, never fetched articles.

## Anonymous discovery protocol
No accounts, cookies or persistent client identifiers. Sharing defaults off. On opting in, the browser obtains a fresh signed token from GET /api/discovery/token and sends its complete list once in POST /api/discovery/submit `{feeds,token}`. Cap: 30; larger lists are rejected instead of silently sending a partial list. Tokens expire in five minutes and are consumed atomically through the existing compare-and-swap database function. They identify one request, not a browser or person. The legacy browser identifier is removed on load. Migration 002 removes old contributor-linked database evidence; this migration is required for an existing installation.

POST /api/discovery/recommendations `{feeds}` queries without contributing; GET /api/discovery/popular lists popular feeds. Both return only aggregate results. Recommendations exclude normalized followed feeds. Ranking is 70% log-scaled co-subscription support plus 30% log-scaled popularity support; at least three accepted batches and weighted support >=2 are required. Large, repetitive or hostname-concentrated lists receive less weight. Each result list includes at most two entries per hostname.

URLs normalize scheme, www, fragments, tracking parameters, slash variants, query order and common feed-path aliases. Publisher-specific aliases with no common canonical relationship cannot always be inferred without content parsing; supplying the publisher's canonical feed is preferred. DNS validation rejects local/private/reserved IPv4 and non-global IPv6 destinations. The proxy validates redirect destinations too.

## Short threat model
Defends against replayed submissions (signed single-use tokens), simple per-network floods (100 requests/minute/instance), duplicate URLs within a batch, inflated low-effort lists, ranking monopolization and fetching recognized private/local addresses. Input is bounded; the database is server-only with RLS. The rate-limit map holds only a server-salted HMAC of a minute-scoped network address with a 60-second logical expiry; raw IP addresses are never retained by application state. Hosting providers may have their own request logs; configure provider logging/retention separately.

Accepts: determined Sybil attackers can obtain fresh tokens from different network addresses; no-account/no-ID discovery cannot reliably deduplicate a returning human across batches. Popularity counts accepted anonymous list submissions, not provably unique clients. Low support produces empty aggregate results; editorial starter suggestions are labeled separately. In-memory network limits are approximate across serverless instances; they complement durable token replay protection, not replace a distributed rate limiter. DNS checks followed by standard fetch still have a DNS-rebinding TOCTOU risk; a pinned-IP transport/egress proxy is recommended before use in sensitive networks. Unusual publisher aliases may remain distinct. Infrastructure-level IP logs are outside the application's no-ID data model.

Stored discovery vote hashes are scoped to a feed pairing and single-use request nonce; they are not reusable client IDs. Replay records expire logically after five minutes and are pruned on subsequent consumption. Existing privacy-sensitive discovery data must be removed using migration 002. Do not claim this app provides cryptographic anonymity or unique-human counts.

## Offline-first behavior
The timeline renders synchronously from a versioned local snapshot before waiting for IndexedDB/network. Articles, sanitized reading HTML, read/saved state and annotations are persisted to IndexedDB and localStorage. IndexedDB writes are serialized and snapshots carry monotonic revisions so old loads/writes cannot replace newer changes. Empty libraries persist too. The app shell and reading dependencies are cached by service worker after one successful online visit; offline article images/fonts are not guaranteed, but downloaded text remains available. Browser clearing/evicting storage cannot be prevented. When both stores fail, the app warns and offline-save does not claim success.

While the app is open, online and visible, cached subscriptions refresh periodically with timeouts/backoff. Refresh merges posts without replacing active story objects, read state, saved state or highlights. Previously downloaded full text is retained. No API content is cached server-side. Use `node scripts/test-offline-first.cjs` and `node scripts/test-feed-refresh.cjs` for storage/refresh regression checks. Real browser service-worker offline reload still needs a deployment-level acceptance test.
`npm.cmd run check`, `node scripts/test-ranking.cjs`, `node scripts/test-discovery-security.cjs`, `node scripts/test-reader-extraction.cjs`.

Deploy by uploading all source files and folders, including lib/discovery-security.cjs and the migrations. Set environment secrets directly in Vercel, never in frontend code/Git. The existing Supabase service key also acts as server-side signing salt through a domain-separated HMAC; rotating it invalidates pending tokens. No additional frontend key is required. Frontend offline caches and highlighted articles remain device-local.
